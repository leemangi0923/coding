# 전북 3과제 · XP-Builder HMI와 XG5000 래더 대조

XP-Builder 3.90의 `전북(26) 3과제.xpd`에서 오브젝트 주소와 버튼 값을 읽고, XG5000 래더 캡처의 0~117번 행과 대조했다. 이 문서는 파일과 캡처를 바탕으로 한 분석이다. 실제 PLC와 장치의 동작은 미검증이다. [전북 3과제 규칙](rules/session-02.md#전북-3과제--탑-정렬)

## 기초검사에서 연결되는 주소

| HMI 조작·표시 | PLC 주소 | 캡처에서 확인한 동작 |
| --- | --- | --- |
| 인덱스 테이블 회전 칸 수 | `D00020` | 요청 칸 수. 누적 이동 칸 수인 `D00040`과 비교한다. |
| IT 정회전 / 역회전 | `D00030`에 각각 `1` / `2` 쓰기 | 정회전은 `D00030.0`, 역회전은 `D00030.1` 분기를 실행한다. |
| IT의 8자리 팩 표시 | `D00050~D00057` | 한 칸 돌 때마다 8자리 값을 순환 이동한다. `D00050`은 12시, `D00054`는 6시 출구에 해당한다. 주소는 12시부터 시계 방향으로 증가한다. |
| 겐트리 좌 / 원점 / 우 | `M00001` / `M00002` / `M00003` | `DST`의 위치 지령 값은 각각 `-100000` / `0` / `100000`이다. |
| 겐트리 위치 표시 | `D00060` | 래더에서 좌 `1`, 원점 `0`, 우 `2`를 기록하고 HMI가 해당 위치를 표시한다. |
| PLC 리셋 | `D00000`에 `1` 쓰기 | `D00000.0`으로 원점 복귀 분기에 들어간다. `FMOV`가 `D00020~D00069`를 0으로 채운다. |

## 인덱스 테이블 회전 흐름

1. HMI에서 회전할 칸 수를 입력하고 방향 버튼을 누른다. 정회전 3칸이면 `D00020=3`, `D00030=1`이다.
2. 요청 칸 수가 0보다 크면 방향별 분기가 `M00077` 펄스를 센다. 정회전은 `C0001`, 역회전은 `C0002`를 쓴다.
3. 카운터가 200에 도달하면 래더가 한 칸 이동으로 처리한다. `WSFTP`와 `MOVP`로 `D00050~D00057` 값을 해당 방향으로 한 자리 순환시키고 `D00040`을 1 올린 뒤 해당 방향 카운터를 리셋한다.
4. `D00040`이 `D00020`과 같아지면 `D00030`과 `D00040`을 0으로 초기화한다. HMI는 회전 후 팩 번호를 각 자리에서 표시한다.

겐트리의 `D00060`은 `DST`와 같은 분기에서 즉시 기록되는 **이동 지시 위치**다. 실제 도착을 확인하는 신호는 캡처 범위에서 확인되지 않았다.

## 동작검사 화면 주소

| 항목 | XP-Builder에서 확인한 주소 또는 쓰기 값 |
| --- | --- |
| 기본값 버튼 | `D00010=1` |
| PLC 리셋 버튼 | `D00010=2` |
| 로봇상태 | `D00073`. 화면 표시는 준비·주행·완료 |
| 주행시간 | `D00099`. 화면 단위는 초 |
| B파레트 이동 카운트 | `D00600` |

동작검사 기본값·리셋의 `D00010` 처리와 로봇상태·주행시간·B 이동 카운트의 갱신 로직은 캡처 범위에서 확인되지 않았다. B 이동 카운트에 쓰는 `D00600`과 IT 회전 칸 수를 세는 `D00040`은 각각의 동작에 대응한다.

전북 3과제에서는 **A의 팩을 잡기 전에** 겐트리의 붉은 선을 해당 번호·문자 표식에 맞춘다. 좌·원점·우 세 좌표는 기초검사에서 확인한 값이고, A의 개별 팩 표식에 맞추는 좌표는 캡처에 제시되지 않았다. **C의 숫자팩을 잡기 전에** IT의 6시 출구에 같은 번호 팩을 맞춘다. HMI에서는 `D00054`가 그 자리를 표시한다.
